# Заселение и аренда — веб-версия

Браузерный компаньон к Android-приложению: тот же REST API, к которому ходит и телефон, так что
запись, добавленная с компьютера, тут же видна в приложении (и наоборот). Node.js 22+ (встроенный
`node:sqlite`), без npm-зависимостей на бэкенде; фронтенд — обычный HTML/CSS/JS (без сборки),
экспорт/импорт Excel — через самостоятельно захостенный SheetJS (`public/js/xlsx.full.min.js`).

## Запуск локально

```bash
cd web
node server.js
# откройте http://localhost:3000
```

Данные хранятся в `web/rental.db` (создаётся автоматически), загруженные чеки — в `web/uploads/`.

## Деплой на Render.com (рекомендуется)

В репозитории уже лежит `render.yaml` (в корне репозитория, не в `web/`) — это Render Blueprint,
описывающий сервис целиком.

1. Зарегистрируйтесь на [render.com](https://render.com) (проще всего — через GitHub).
2. **New +** → **Blueprint**.
3. Выберите этот репозиторий (и нужную ветку — например `claude/new-session-o6xs1b`, пока это не
   влилось в основную ветку).
4. Render прочитает `render.yaml` и предложит создать веб-сервис `hr-housing-web` — подтвердите.
5. Дождитесь окончания деплоя (несколько минут на первый билд) — Render покажет публичный адрес
   вида `https://hr-housing-web.onrender.com`.
6. Откройте этот адрес в браузере — это и есть сайт для заполнения с компьютера.
7. В Android-приложении в разделе «Настройки» укажите этот же адрес — тогда телефон будет читать и
   писать в ту же базу, что и сайт.

### Как данные переживают бесплатный тариф Render

На бесплатном плане Render диск не сохраняется между перезапусками контейнера (а перезапуски там
случаются регулярно — в том числе просто от «сна» после периода без запросов), поэтому файл
SQLite сам по себе будет стираться. Чтобы обойтись без платного диска (~$7/мес), сервер умеет
делать резервную копию файла базы в Google Диск и восстанавливать её оттуда при каждом запуске —
это уже встроено в `server.js` (`web/drive.js`), просто нужно один раз настроить доступ:

1. Откройте [console.cloud.google.com](https://console.cloud.google.com/), создайте новый проект
   (бесплатно).
2. В разделе **APIs & Services → Library** найдите **Google Drive API** и нажмите **Enable**.
3. В разделе **APIs & Services → Credentials** → **Create Credentials** → **Service Account**.
   Имя — любое, роль можно не назначать.
4. Откройте созданный сервисный аккаунт → вкладка **Keys** → **Add Key** → **Create new key** →
   тип **JSON**. Скачается файл — это и есть `GDRIVE_SERVICE_ACCOUNT_JSON` (весь его текст целиком).
5. Внутри скачанного JSON найдите поле `client_email` (что-то вроде
   `xxx@yyy.iam.gserviceaccount.com`) — это email сервисного аккаунта.
6. В своём обычном Google Диске создайте папку (например «Заселение и аренда — бэкап»), откройте
   её «Настройки доступа» → **Поделиться** → вставьте email из шага 5 → дайте роль **Редактор**.
7. Скопируйте ID этой папки — это часть ссылки после `folders/`, например
   `https://drive.google.com/drive/folders/1AbCdEfGhIjKlMnOpQrSt` → ID = `1AbCdEfGhIjKlMnOpQrSt`.
   Это значение для `GDRIVE_FOLDER_ID`.
8. На Render: сервис → **Environment** → добавьте `GDRIVE_SERVICE_ACCOUNT_JSON` (вставьте весь
   JSON целиком) и `GDRIVE_FOLDER_ID` (ID папки из шага 7) → **Save Changes** (сервис перезапустится).

После этого при каждом перезапуске сервер сам подтянет последнюю копию базы из этой папки на
Диске, а после каждого изменения данных (с задержкой ~8 секунд, чтобы не заливать копию на
каждый чих) сам обновит файл в этой же папке. Ничего вручную нажимать не нужно.

Если не настраивать Google Диск — сервер всё равно работает, просто на бесплатном тарифе Render
данные будут пропадать при перезапуске контейнера. В таком случае реальный выход — платный план
Starter (~$7/мес) с постоянным диском: добавьте в `render.yaml` блок

```yaml
    plan: starter
    disk:
      name: hr-housing-data
      mountPath: /var/data
      sizeGB: 1
    envVars:
      - key: DB_PATH
        value: /var/data/rental.db
      - key: UPLOADS_PATH
        value: /var/data/uploads
```

**Важно:** резервная копия в Google Диск покрывает только файл базы данных (все 11 разделов,
кроме содержимого самих файлов чеков). Загруженные файлы чеков (`web/uploads/`) на бесплатном
плане без диска не переживут перезапуск — это можно скачивать в SAF/локально на телефоне (там
чеки не привязаны к серверу), либо перейти на платный диск, если важны именно файлы чеков на сайте.

## REST API (кратко)

Все ресурсы, кроме `shared-fields`/`templates`, — обычный CRUD над JSON-объектами, повторяющими
поля Kotlin-моделей Android-приложения один в один:

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/trip-entries` | Список записей «Входная информация» |
| POST | `/api/trip-entries` | Создать запись |
| PUT | `/api/trip-entries/:id` | Обновить запись |
| DELETE | `/api/trip-entries/:id` | Удалить запись |
| GET/POST/PUT/DELETE | `/api/rental-records[...]` | То же для «База данных» аренды |
| GET/POST/PUT/DELETE | `/api/landlords[...]` | Арендодатели |
| GET/POST/PUT/DELETE | `/api/residents[...]` | Проживающие сотрудники |
| GET/POST/DELETE | `/api/cities[...]` | Города |
| POST | `/api/cities-reset` | Сбросить города к списку по умолчанию |
| GET/POST/DELETE | `/api/finance-registry[...]` | Реестр согласований с финансами |
| GET | `/api/shared-fields` | Текущее состояние «сквозных» полей (ФИО/город/даты/…) |
| PUT | `/api/shared-fields` | Частичное обновление (merge) |
| GET | `/api/templates` | Все три редактируемых шаблона текста |
| PUT | `/api/templates/:key` | Обновить один шаблон (`CHECKIN`/`BOOKING`/`FINANCE_OBJECT`) |
| POST | `/api/upload` | Загрузить файл чека (тело — сырые байты, заголовок `X-Original-Filename`) |
| DELETE | `/api/all-data` | Полная очистка (аналог кнопки «Удалить все данные») |

## Тестирование

Весь фронтенд прогнан через headless Chromium (Playwright) с реальными кликами по всем 11
разделам плюс сквозным round-trip тестом парсинга Excel-заголовков — это не Claude Artifact, а
обычный сайт, так что тестировался по-настоящему, а не только на глаз.

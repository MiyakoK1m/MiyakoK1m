# Промпт для создания Android-приложения «Заселение и аренда»

Скопируй всё, что ниже, и вставь в нейросеть (например, в чат, который умеет писать Android-приложения — Kotlin/Jetpack Compose или аналог).

---

## Контекст и назначение

Разработай Android-приложение для внутреннего использования HR-отделом компании (аренда жилья для сотрудников в командировках, Казахстан). Приложение заменяет собой набор Excel-таблиц и текстовых шаблонов, которыми сейчас пользуется HR-менеджер вручную. Один пользователь, работает преимущественно оффлайн, все данные хранятся локально на устройстве (Room/SQLite или аналог), интерфейс на русском языке.

Общий принцип: пользователь вводит данные один раз в любом разделе — и они автоматически подставляются во всех связанных разделах (см. раздел «Сквозная синхронизация полей» ниже). На основе введённых данных формируются готовые тексты сообщений (для арендодателя, для сотрудника, для согласования с финансами), которые можно скопировать одним нажатием.

Все денежные суммы — в тенге (₸), формат с разделением разрядов. Все даты отображаются в формате ДД.ММ.ГГГГ. Текущее время/дата везде считается по часовому поясу UTC+5 (Алматы/Астана), независимо от часового пояса устройства.

---

## Разделы приложения (экраны/вкладки)

Реализуй следующие 11 разделов. На телефоне это должно быть выдвижное боковое меню (Navigation Drawer) со списком разделов в столбик — не горизонтальные вкладки и не нижняя навигация (в них плохо помещается 11 пунктов).

1. **Входная информация** — форма командировки
2. **Дэшборд** — кто сейчас проживает и тепловая карта по городам
3. **Календарь** — календарь заселений/выселений
4. **Информация по заселению** — шаблон текста для сотрудника
5. **Бронирование** — шаблон текста подтверждения брони
6. **Согласование с финансами** — шаблон текста + реестр согласований
7. **База данных** — основная база записей об аренде
8. **Информация по аренде** — тот же список, что и «База данных», но в виде редактируемой таблицы целиком
9. **Арендодатели** — справочник арендодателей
10. **Проживающие сотрудники** — список сотрудников с пометкой «уже где-то проживает»
11. **Города** — редактируемый список городов для автоподсказок

## 1. Входная информация

Форма для регистрации командировки. Поля:

- **ФИО проживающих** — динамический список (можно добавлять/удалять несколько человек кнопкой), каждое поле — отдельное текстовое поле для одного ФИО
- **Должность** — текст, обязательное
- **Департамент** — выпадающий список (реальные отделы компании): IT, БиОТ, Инфраструктура, Коммерческий департамент, Логистика, НО, Отдел кадров, Проектный и процессный отдел, СБ, СП, Склад
- **Вид жилья** — выбор плиткой: Квартира / Отель, обязательное
- **Командировка вне регламента** — выбор плиткой: Нет / Да, обязательное. При выборе «Да» плитка подсвечивается красным (это флаг для проверяющих, что поездка — исключение из обычного порядка)
- **Город назначения** — текстовое поле с автоподсказкой из редактируемого списка городов (раздел «Города»), свободный ввод не блокируется
- **Дата заселения** / **Дата выселения** — выбор даты
- **Сумма суточных, ₸** — число
- **Причина срочности** — текст, необязательное
- **Обоснование командировки** — многострочный текст, обязательное
- Отдельной секцией/панелью: **Цель поездки** — выбор плиткой: «В рамках открытия складов» / «Другое». При выборе «Другое» никакого дополнительного текстового поля не открывается — фиксируется буквальное значение «Другое»
- Отдельной секцией/панелью: **Цель поездки (другое)** — многострочное текстовое поле, где пользователь при необходимости пишет развёрнутую альтернативную формулировку цели поездки (независимо от того, что выбрано выше)

### Проверки и подсказки на этом экране (обновляются в реальном времени при вводе)

- **Панель «Проверка по списку "Проживающие сотрудники"»**: сверяет каждое введённое ФИО со справочником «Проживающие сотрудники» (сопоставление нечёткое — по совпадению слов ФИО, без учёта регистра и порядка «Имя Фамилия» / «Фамилия Имя»). Если совпадение найдено — выводится видимая строка вида «⚠ Иванов Иван — [комментарий из справочника]» (не просто всплывающая подсказка, а постоянно видимый текст).
- **Панель «История командировок в этот город»**: если по введённым ФИО + городу находится ранее сохранённая запись в этом же разделе с тем же городом — выводится: «⚠ Иванов Иван уже был(а) в командировке в этом городе: 01.06.2026 – 05.06.2026 — «[обоснование той поездки]»».

## 2. Дэшборд

Экран для быстрого обзора текущей ситуации.

### Блок «Кто сейчас проживает и в каком городе»
Таблица/список сотрудников, у которых **сегодняшняя дата** (по UTC+5) попадает в диапазон [дата заселения; дата выселения] из раздела «Входная информация». Столбцы: ФИО, Департамент, Город назначения, Комнат в квартире (подтягивается из «Базы данных» через сопоставление по ФИО+датам, если найдено совпадение — иначе прочерк), Заселён с, Выселяется. Если дата выселения — сегодня, эта дата подсвечивается красным со значком ⚠. Сверху — сводка: «Сейчас проживает: N чел. в M городах». Кнопка ручного обновления, но список пересчитывается автоматически при любом изменении данных.

### Блок «Тепловая карта загруженности по городам»
Плитки городов (не календарная сетка, а именно карточки по городам), отсортированные от самого загруженного к наименее загруженному. В каждой плитке: название города, крупное число — сколько человек сейчас там проживает (тот же критерий «сегодня в диапазоне»). Цвет плитки — по интенсивности от светло-серого (мало) до тёмно-синего (максимум прямо сейчас), 5 ступеней. Легенда «Меньше → Больше» под картой.

---

## 3. Календарь

Помесячный календарь (навигация ‹ месяц год ›, кнопка «Сегодня»). В каждой ячейке дня — «плитки»-бейджи по каждому активному в этот день человеку, источники — «Входная информация» и «База данных» одновременно:

- Если запись есть **только** во «Входной информации» — обычная синяя плитка с ФИО.
- Если находится совпадающая запись в «Базе данных» (сопоставление по ФИО + пересечению дат) — плитка получает значок 🏠, при клике показываются также данные аренды (адрес, ставка, депозит, статус возврата депозита).
- Если запись есть **только** в «Базе данных» (нет привязанной командировки во «Входной информации») — зелёная плитка со значком 🔑.
- В день, совпадающий с датой выселения, соответствующая (только эта) плитка подсвечивается красным — напоминание о необходимости вернуть депозит.

Клик по плитке открывает панель деталей с полной информацией.

---

## 4. Информация по заселению

Генератор текстового шаблона для отправки сотруднику. Поля ввода:

- ЖК (жилой комплекс), Адрес, Подъезд (+ примечание), Этаж, Номер квартиры, Тип квартиры (плитка: Студия / 1-комнатная / 2-комнатная / 3-комнатная / 4-комнатная / «Другое» с полем ввода), Код домофона
- **Дата заселения / Дата выселения** (синхронизируются с другими разделами)
- Время заселения (с) / Время выселения (до) — текст
- Ссылка на 2ГИС — текст названия + текст URL, в готовый текст подставляется в формате Markdown-ссылки `[текст](url)`
- Имя Wi-Fi сети, пароль Wi-Fi
- Переключатель (чекбокс) «Включить стандартный блок правил проживания» — если включён, в готовый текст добавляется блок:
  ```
  Правила проживания:
  • Курение в квартире запрещено
  • Просьба поддерживать чистоту: не оставлять после себя беспорядок, не наносить ущерб имуществу, бережно относиться к постельному белью и полотенцам
  • С 23:00 соблюдать тишину, уважая соседей
  • При вызове полиции из-за нарушения тишины или иных правил ответственность несёт сотрудник
  • При нарушении правил проживания возвратный депозит не возвращается — ответственность также несёт сотрудник
  ```
- Дополнительный комментарий — многострочный текст
- Готовый текст собирается автоматически в реальном времени из редактируемого шаблона (пользователь может менять формулировки шаблона, вставляя токены вида `{жк}`, `{адрес}`, `{дата_заезда}` и т.д.) и выводится в текстовое поле только для чтения с кнопкой «Скопировать».

---

## 5. Бронирование

Генератор текста подтверждения брони для арендодателя. Поля: ФИО гостей (динамический список), Город, ЖК, Адрес, Тип квартиры, Даты заезда/выезда, Время заезда/выезда, Стоимость за сутки, Депозит, Итого (авто-расчёт = депозит + ставка × количество суток). Готовый текст — аналогично, редактируемый шаблон + токены + кнопка «Скопировать».

## 6. Согласование с финансами

### Форма согласования
Один или несколько «объектов» согласования (кнопка «+ Добавить объект» создаёт следующий, у каждого своя кнопка «Удалить объект»). Поля каждого объекта: Город (с автоподсказкой городов), ФИО, Тип квартиры (плитка), Количество гостей, Даты заезда/выезда, Стоимость за сутки, Депозит, Итого (авто-расчёт), Комментарий.

**Важно:** поле «Количество гостей» **основного** (первого) объекта автоматически считается как количество ФИО, введённых в списке гостей на «Бронировании» / «Входной информации» — пользователю не нужно вводить число вручную для первого объекта.

Готовый текст: по каждому объекту — блок текста по шаблону, если объектов больше одного — в конце добавляется «Итоговая сумма: X ₸» (сумма всех объектов).

### Реестр согласований с финансами
Отдельная, независимая таблица (собственное хранилище, не связано с «Базой данных»). Кнопка «Сохранить в реестр» записывает текущие объекты согласования отдельными строками (дата сохранения, город, ФИО, тип квартиры, гостей, суток, даты, ставка, депозит, итого, комментарий). У каждой строки — кнопка «Удалить».

**Механизм повторного использования записей:** в таблице реестра у каждой строки есть чекбокс. Кнопка «➕ Добавить выбранные строки как объекты» — берёт отмеченные галочками строки реестра и создаёт из них объекты согласования в форме выше (первая отмеченная запись заполняет основной объект, если он пуст; остальные автоматически создают новые объекты). Так пользователь может быстро повторно отправить на согласование ранее сохранённые заявки.

Кнопка «Скачать Excel» экспортирует реестр.

## 7. База данных (главная таблица аренды)

Основная форма ввода записи об аренде — самая подробная. Поля:

- Код аэропорта города (выпадающий список кодов для ~20 крупных городов Казахстана)
- Город (автоподсказка)
- Периодичность — плитка: Ежедневно / Ежемесячно
- Дата начала аренды / Дата завершения аренды
- Срок аренды в днях
- Сумма аренды (ставка за день/месяц)
- Итого сумма аренды (авто-расчёт = ставка × срок)
- Дата оплаты аренды
- Сумма депозита
- Статус возврата депозита — плитка: (не указано) / Вернули / У арендатора
- Департамент (тот же список, что и во «Входной информации»)
- ФИО (получатель аренды)
- Цель поездки / Цель поездки (другое) — те же концепции, что и во «Входной информации»
- Кол-во комнат (авто-подставляется по выбранному типу квартиры, но редактируемо)
- Сколько проживает гостей
- Экономия при 2-х местном размещении, ₸
- Экономия при 1-о местном размещении, ₸
- Адрес
- Тип квартиры — плитка: Студия / 1..4-комнатная / Другое (с полем ввода)
- Квартплата, ₸
- Блок «Контакты арендодателя»: ФИО арендодателя, Телефон, Способ оплаты (плитка: Счёт / Перевод), Рейтинг арендодателя (плитка 1–10)
- Возможность прикрепить файл чека: при выборе файла (любого формата — не ограничивать типом) система спрашивает текстом «Что это за чек?» и переименовывает файл в формат `{дата_начала_аренды}_{город}_{ФИО}_{описание}.{расширение исходного файла}`, затем предлагает сохранить в выбранную пользователем папку на устройстве (или через стандартный Android "Save As"/Storage Access Framework). Имя сохранённого файла отображается в записи.

### Отображение таблицы
- Таблица показывает записи, отсортированные от самой новой даты начала аренды к самой старой.
- По умолчанию видно только **последние 5 записей**, кнопка «Показать все записи (N)» разворачивает полный список (сортировка и лимит влияют только на отображение — хранение и экспорт всегда идут в естественном порядке).
- Кнопка «🗑️ Удалить все данные» — с двойным подтверждением: обычный диалог + требование вручную ввести слово «УДАЛИТЬ» — полностью очищает все данные приложения (не только эту таблицу, а вообще всё: базу аренды, входную информацию, арендодателей).
- Импорт из Excel/CSV: сопоставление столбцов по заголовку — сначала точное совпадение текста заголовка, если не найдено — по частичному совпадению (чтобы файлы с чуть другой формулировкой заголовков всё равно подхватывались).
- Отдельная кнопка импорта, понимающая специфический формат выгрузки из внешней корпоративной системы учёта командировок (готова к настройке маппинга конкретных столбцов под реальный экспортный файл компании).
- Кнопка «Скачать Excel» — только Excel, без CSV/JSON в выгрузке.
- Кнопка «Резервное копирование» — сохраняет ВСЕ разделы (База данных, Входная информация, Арендодатели и т.д.) в один Excel-файл, один раздел — один лист. Кнопка «Восстановить из копии» — читает такой файл и добавляет отсутствующие записи (без дублей) в соответствующие разделы.

## 8. Информация по аренде

Та же самая база данных, что и в разделе 7, но отображается **полностью** (все столбцы, включая расширенные технические поля — ЖК, подъезд, этаж, домофон, Wi-Fi и т.д.) в виде таблицы, где **каждая ячейка редактируется прямо в таблице** (клик — редактирование на месте, при потере фокуса — сохранение и автоформатирование чисел/дат). Поиск по ФИО с автоподсказкой. Кнопки импорта/экспорта — как в разделе 7.

---

## 9. Арендодатели

Независимый справочник. Поля: ФИО арендодателя, Контактный номер, **Собственник или риелтор** (плитка), Город, Способ оплаты (плитка), Рейтинг (плитка 1–10), Комментарий. Таблица со всеми записями, кнопка удаления у каждой строки, экспорт в Excel.

Эти данные также подтягиваются в виде вспомогательной панели «Арендодатели в этом городе» на разделе «Входная информация»: при заполнении города там показываются подходящие арендодатели, отсортированные по рейтингу (зелёный бейдж рейтинга ≥7, жёлтый ≥4, красный <4), с кнопкой быстрого перехода в WhatsApp (сообщение автоматически подставляет ФИО, город, даты).

---

## 10. Проживающие сотрудники

Независимый справочник для предупреждений (описан в разделе 1). Поля: ФИО сотрудника, Комментарий (например: «Проживает в Алматы до 20.08.2026»). Таблица, удаление, экспорт в Excel.

---

## 11. Города

Редактируемый список городов, используемый как источник автоподсказок во всех полях «Город» по всему приложению. По умолчанию заполнен 20 крупными городами Казахстана (Астана, Алматы, Шымкент, Караганда, Актобе, Атырау, Усть-Каменогорск, Тараз, Талдыкорган, Уральск, Костанай, Кызылорда, Актау, Павлодар, Петропавловск, Туркестан, Жезказган, Конаев, Семей, Кокшетау). Кнопки: добавить город, удалить конкретный город, «Восстановить список по умолчанию». Автоподсказка не блокирует свободный ввод — можно ввести город, которого нет в списке.

## Сквозная синхронизация полей

Реализуй единый механизм: изменение значения в одном поле мгновенно обновляет то же самое поле во всех остальных разделах, где оно встречается (двусторонняя синхронизация в реальном времени, без необходимости сохранять форму). Группы синхронизированных полей:

- ФИО гостей: Бронирование ↔ Финансы (ФИО) ↔ Входная информация
- Город: Бронирование ↔ Финансы ↔ Входная информация
- Адрес: Бронирование ↔ Заселение
- ЖК: Бронирование ↔ Заселение
- Тип квартиры: Бронирование ↔ Финансы ↔ Заселение ↔ База данных
- Дата заселения: Бронирование ↔ Финансы ↔ Входная информация ↔ Заселение
- Дата выселения: аналогично
- Количество суток: Бронирование ↔ Финансы
- Ставка за сутки: Бронирование ↔ Финансы
- Депозит: Бронирование ↔ Финансы
- Итого: Бронирование ↔ Финансы
- Время заселения/выселения: Заселение ↔ Бронирование

## Общие требования к оформлению

- **Тёмная и светлая тема** с переключателем (кнопка с иконкой 🌙/☀️), выбор запоминается между запусками, тёмная тема применяется сразу при запуске без «мигания» светлой.
- Мобильный интерфейс: крупные, удобные для пальца элементы управления, поля ввода без риска нежелательного масштабирования при фокусе.
- Все таблицы должны корректно прокручиваться сами по себе (горизонтально при необходимости), не растягивая экран целиком.
- Длинный текст в ячейках таблиц переносится по границам слов (не разрывая слово посередине); для ФИО — то же самое; для дат, сумм и кнопок «Удалить» перенос запрещён (всегда в одну строку).
- Длинные текстовые поля (например, «Причина срочности») в таблице показываются сокращённо с многоточием «…», клик по которому разворачивает/сворачивает полный текст на месте.
- Плавающие кнопки «прокрутить в начало» / «прокрутить в конец» (актуально скорее для длинных списков — на Android это может быть реализовано как FAB с прокруткой RecyclerView/LazyColumn к началу/концу).

## Технический стек (рекомендация, не обязательна к исполнению буквально)

- Kotlin + Jetpack Compose, Material 3 (с поддержкой светлой/тёмной темы через тему приложения)
- Room (SQLite) для локального хранения всех разделов
- DataStore для хранения настройки темы и прочих пользовательских предпочтений
- Экспорт/импорт Excel — библиотека Apache POI или аналог
- Storage Access Framework (SAF) для сохранения файлов чеков и резервных копий в выбранную пользователем папку
- Часовой пояс UTC+5 (Asia/Almaty) — использовать явно указанную зону, не системную зону устройства, для всех расчётов «сегодня», календаря и дэшборда
